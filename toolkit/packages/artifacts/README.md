# @rtk/artifacts

Safe archive inspection and extraction. Every public entry point returns an `Evidence` record (`@rtk/evidence`), provider `rtk-artifacts`, authority `shipped-artifact`, confidence `observed`, with explicit `limitations`.

```ts
inspectArchive(path, quotas?: Partial<Quotas>): Promise<Evidence>               // operation "inspect_archive"
extractArchive(path, destDir, quotas?, { policy?: "strict"|"skip-bad", preserveExec?: boolean }): Promise<Evidence>  // "extract_archive"
```
CLI: `node bin/rtk-artifacts.ts inspect <archive>` / `extract <archive> <dest> [--policy strict|skip-bad] [--quota maxRatio=50]` (JSON on stdout; exit 0 ok, 1 anomalies/failed, 2 usage).

## What it does
* Formats (by magic, not extension): zip (jar/apk/ipa/aar/docx/xlsx/pptx flavour detected from structure), tar (ustar, GNU long names, pax path/linkpath/size), tar.gz / plain gzip, Electron `.asar` (own header parser; `@electron/asar` is a devDependency used only to build test fixtures). Nested zip/gzip/tar/asar found in entries are inspected recursively up to `quotas.maxDepth` with a shared byte budget.
* Inventory per entry: path, type, kind (elf, pe, macho, dex, java-class, script, zip, gzip, tar, asar, android-binary-xml, wasm, sqlite, pdf, image, xml, text, data...), actual and declared size, compressed size, CRC32 (zip), sha256, mode, link target, encryption flag, method, anomaly codes.
* Anomaly codes (machine-readable, with severity): `path-traversal`, `absolute-path`, `drive-letter`, `control-char` (incl. NUL), `empty-name`, `name-too-long`, `symlink`, `symlink-escape`, `symlink-through`, `hardlink`, `hardlink-escape`, `device-node`, `special-file`, `special-mode` (setuid etc.), `duplicate-name`, `case-collision`, `encrypted-entry`, `unsupported-compression`, `size-mismatch`, `crc-mismatch`, `integrity-mismatch` (asar sha256), `local-header-mismatch` (zip), `asar-offset-out-of-range`, `asar-overlap`, `asar-unpacked-external`, `corrupt-archive`, `entry-count-mismatch`, quota breaches `entry-count-exceeded` / `total-size-exceeded` / `entry-size-exceeded` / `ratio-exceeded` / `depth-exceeded` / `nested-too-large`, plus extraction-time `would-overwrite`, `path-conflict`, `unsupported-format`.
* Quotas (`DEFAULT_QUOTAS`): 10 000 entries, 1 GiB total, 512 MiB per entry, ratio 100:1 (checked once an entry exceeds 64 KiB), depth 3, name length 4096, 64 MiB nested buffer. Enforced WHILE STREAMING: declared sizes are never trusted (an entry that produces more than it declared is aborted at declared+1 bytes; ratio/total/entry quotas abort mid-stream; zip entry counts are checked from the central directory before reading anything).
* Extraction is safe by construction: listing-level refusals happen before anything is written; each path component is `lstat`ed and `realpath`ed after creation (an existing symlink in the way is refused); files are opened `O_CREAT|O_EXCL|O_NOFOLLOW` (never overwrite — existing files are left untouched, also by cleanup); symlinks, hardlinks, devices and FIFOs are NEVER created (reported); files are written 0600 (0700 with `preserveExec`), dirs 0700, setuid/setgid/sticky never preserved. `strict` (default) fails the whole extraction on the first refused entry; `skip-bad` skips refused entries and reports them. Quota breaches fail everything under both policies. On failure everything created is removed (including destination directories it created) and the Evidence says `status: "failed"`, `failure: {code, entry, detail}`, `cleaned_up: true`. Success returns a manifest with sha256 of every extracted file.

## Verification (`npm test`, 31 tests, 0 skipped on this lab)
Malicious archives are generated at test time by `test/support/make_archives.py` (python3 zipfile/tarfile + Info-ZIP `zip -P` + hand-patched headers). For each, the test asserts inspect reports the specific code, strict extraction fails with that `failure.code`, and a recursive snapshot (path/type/size/sha) of the whole sandbox including siblings is byte-identical before and after (nothing outside dest, partial output cleaned): zip-slip, absolute path, drive letter, backslash traversal, symlink to /etc, symlink-then-file-through-symlink (escaping and internal), pre-existing symlinked parent, zip bomb (20 MiB -> 20 KB), total/per-entry quota on incompressible data, declared-size lies (smaller, larger, lying bomb), CRC corruption, 200 entries over a quota of 100, duplicate names, case collisions, control chars, NUL, ZipCrypto encrypted entry, tar with `../`, absolute, device, fifo, symlink, hardlink, 8-level nesting bomb, nested ratio bomb, tar.gz bomb, truncated/garbage inputs, never-overwrite, modes. Legit: tar/tar.gz (manifest, long names), plain gzip, kinds by magic + nested recursion, an `.asar` built by `@electron/asar` (file offsets re-derived independently from the raw header and compared with our sha256s and with the asar integrity hashes; tamper detection), hand-built asar with out-of-range/overlapping offsets and `../` keys, CLI exit codes. Lab-sample tests (`sample.zip`, `apk/demo-unsigned.apk`: `classes.dex` kind=dex, `AndroidManifest.xml` present, manifest equals python zipfile's hashes) skip cleanly if `/tmp/claude-0/.../scratchpad/samples` is absent.

## Not implemented / not verified
7z, rar, xz, bzip2, zip AES/encrypted contents (detected only), zip methods other than stored/deflate (`unsupported-compression`), multi-volume zips, tar sparse/multi-volume, creating symlinks (deliberately never), recursive extraction of nested archives (they are written as plain files). Zip names without the UTF-8 flag are decoded as Latin-1 not CP437; Info-ZIP unicode-path extra fields are ignored. Race conditions with a concurrent local attacker on the destination are out of scope. Android binary XML is not decoded. Not tested on Windows/macOS or case-insensitive filesystems. Memory: nested archives up to `maxNestedBytes` are buffered; top-level gzip is spooled to a private temp file.
